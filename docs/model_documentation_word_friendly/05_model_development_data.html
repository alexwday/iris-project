5. Model Development Data

5.1 Data Validity and Sources

The IRIS system retrieves information from a collection of internal and external accounting and finance knowledge sources stored in a PostgreSQL database. The data spans the full history of RBC Finance policy documentation, including current policy manuals, updated procedures, and archived reference materials, ensuring comprehensive coverage across time periods. All data is sourced from authorized RBC repositories in compliance with enterprise data management standards.

IRIS accesses data covering several key domains including Internal RBC Policies, Accounting Guidelines developed by RBC Finance, Internal Documentation like accounting memos and project approval requests, Financial Reporting information, and Accounting Standards from external sources. This domain-focused coverage enables IRIS to address finance and accounting inquiries relevant to RBC Finance.

Data quality is maintained through several validation mechanisms. During initial ingestion, all documents undergo integrity checks for completeness and readability. Documents with corrupt content, excessive missing sections, or formatting issues that would impact interpretability are flagged for manual review before inclusion. These validation processes ensure the data maintains sufficient quality for reliable retrieval and information extraction.

The system stores processed documents in a PostgreSQL database with a structured schema designed to support both catalog-based and semantic search approaches. The database schema is defined in the postgres_schema.sql file and includes tables for document metadata, content storage, vector embeddings, and performance monitoring. All data sources are obtained and managed in compliance with RBC's enterprise data management processes and data governance requirements.

Data timeliness is maintained through scheduled quarterly updates for internal policy documentation, ensuring that responses reflect current policies. External accounting standards are refreshed following significant updates to IFRS and other relevant frameworks, typically on an annual basis or more frequently when major changes occur.

The document processing framework transforms source documents into formats optimized for different retrieval methods through several steps: Source Identification from designated storage locations, Format Conversion from various formats to standardized markdown, Structure Preservation to maintain document hierarchies, Metadata Generation including summaries and contextual information, and Storage Optimization for efficient retrieval.

Each processing pipeline employs specialized metadata generation approaches tailored to document types. For standard documents, document-level summaries and descriptions are created. For larger documents with sections, both document and section-level summaries are generated. For Excel files, tabular structure is preserved in the metadata. Visual content is processed using the Qwen2 vision model to extract and describe visual elements. For large reference materials, comprehensive recursive metadata is generated at both chapter and section levels to support sophisticated retrieval.

5.2 Data Cleaning and Processing

IRIS implements several data cleaning and processing steps to ensure that source documents are properly formatted and optimized for retrieval. Each document undergoes processing specific to its format and content type:

Document Normalization: All documents are converted to a standardized markdown format, removing inconsistent formatting while preserving essential structural elements. This normalization affects approximately 95% of all incoming documents, with the remaining 5% requiring manual intervention due to complex formatting or non-standard elements.

Missing Data Handling: Documents with missing sections or incomplete content are handled through a specialized process. For minor gaps (affecting less than 5% of document content), contextual inference is used to fill in missing information. For larger gaps (5-20% of content), the missing sections are explicitly marked as unavailable, ensuring transparency about information completeness. Documents missing more than 20% of critical content are flagged for manual review before inclusion in the database.

Structural Cleaning: Duplicate sections, redundant headers, and formatting artifacts are removed during processing. This cleaning step affects approximately 35% of documents, with an average reduction in token count of 12% while preserving all substantive content.

Language Standardization: Inconsistent terminology, abbreviations, and acronyms are standardized according to RBC Finance glossaries. This process affects approximately 40% of documents and ensures consistent retrieval regardless of specific terminology variations used in queries.

The data cleaning process is consistently applied across all document types, with specific variations based on the document format and content type. For example, financial spreadsheets undergo additional processing to ensure tabular data is preserved in a readable format, while visual documents receive specialized processing to extract and structure visual information.

For upstream models that generate embeddings, the data undergoes additional preprocessing including stopword removal, lemmatization, and special character handling to optimize vector representations. This processing affects the embedding quality but does not alter the original content available for retrieval and presentation.

IRIS uses a sequential processing approach that begins with the conversation history as the initial input. For each query, the Agent Router analyzes this history to determine the appropriate processing path. Queries following the Direct Response path rely primarily on the conversation history, while those following the Research path require additional database access and processing.

For research queries, the system performs a structured information retrieval process that begins with the Clarifier Agent ensuring sufficient context is available. The Planner Agent then analyzes this context to select the most relevant knowledge sources. Database Subagents query the PostgreSQL database to retrieve relevant document content and metadata, using specialized retrieval methods based on the selected sources.

The vector embeddings input is particularly critical for semantic search operations, as it enables the system to identify the most relevant document chunks based on semantic similarity rather than simple keyword matching. These embeddings are generated using the text-embedding-3-large model and stored in the database for efficient retrieval.

Expert-driven inputs, including agent prompts and process parameters, are developed based on extensive testing and refinement by subject matter experts. These inputs are carefully crafted to optimize system performance across various query types and knowledge domains.

For cases where data is missing or unavailable in the knowledge base, the system explicitly acknowledges these limitations in its responses, ensuring transparency about information completeness. This approach ensures that users are aware of potential information gaps and can seek additional resources if needed.

5.4 Data Assumptions and Limitations

Despite IRIS's robust data processing framework, certain assumptions and limitations affect its operation. In cases where data requirements are not fully met, the system implements a gap analysis process to identify missing information and prioritize future data collection efforts. This process includes tracking common query topics that lack sufficient documentation, monitoring response quality metrics, and gathering user feedback on information completeness.

These limitations are actively managed through several risk mitigation strategies. For Content Currency, the system includes version information and last-update timestamps in responses to ensure users are aware of potential staleness. The Visual Content limitation is addressed by providing text descriptions of complex visuals and referring users to original documents when detailed visual information is critical. For Information Boundaries, the system explicitly acknowledges when information may be incomplete and suggests alternative resources when appropriate.

The IRIS system is designed for continuous improvement through regular documentation updates and processing enhancements. Documentation updates include scheduled refresh cycles to incorporate policy changes and expansion of the knowledge base to cover additional finance domains. Processing enhancements focus on improvements to visual content processing for complex financial diagrams and better preservation of document relationships and cross-references. The system's modular design allows for component-level improvements without requiring complete system redesign.

5. Model Development Data

5.1 Data Validity and Sources

The IRIS system retrieves information from a collection of internal and external accounting and finance knowledge sources stored in a PostgreSQL database. This section describes the data used by the system, its sources, and processing methods.

IRIS accesses data covering several key domains including Internal RBC Policies, Accounting Guidelines developed by RBC Finance, Internal Documentation like accounting memos and project approval requests, Financial Reporting information, and Accounting Standards from external sources. This domain-focused coverage enables IRIS to address finance and accounting inquiries relevant to RBC Finance.

The system stores processed documents in a PostgreSQL database with a structured schema designed to support both catalog-based and semantic search approaches. The database schema is defined in the postgres_schema.sql file and includes tables for document metadata, content storage, vector embeddings, and performance monitoring.

The document processing framework transforms source documents into formats optimized for different retrieval methods through several steps: Source Identification from designated storage locations, Format Conversion from various formats to standardized markdown, Structure Preservation to maintain document hierarchies, Metadata Generation including summaries and contextual information, and Storage Optimization for efficient retrieval.

Each processing pipeline employs specialized metadata generation approaches tailored to document types. For standard documents, document-level summaries and descriptions are created. For larger documents with sections, both document and section-level summaries are generated. For Excel files, tabular structure is preserved in the metadata. Visual content is processed using the Qwen2 vision model to extract and describe visual elements. For large reference materials, comprehensive recursive metadata is generated at both chapter and section levels to support sophisticated retrieval.

5.2 Document Processing Pipelines

IRIS uses five specialized document processing pipelines, each optimized for specific document types and formats. These pipelines transform source documents into formats suitable for efficient retrieval.

The Catalog Search - Small pipeline is designed for standard documents such as Project Approval Requests. It converts documents to markdown format, keeps documents whole without chunking, and generates document-level summaries for catalog selection. This streamlined approach is suitable for documents under 10,000 tokens, providing efficient retrieval without unnecessary complexity.

For large documents with distinct sections, like Corporate Accounting Policy Manuals, the Catalog Search - Large pipeline splits documents into logical sections based on headings and creates both document-level and section-level summaries. This enables a sophisticated two-stage retrieval process where the system first selects relevant documents and then identifies specific sections within those documents, providing more precise information access.

The Catalog Search - Excel pipeline is specialized for handling spreadsheet content from sources like Wiki entries. It preserves table structures while converting content to markdown format, processing each row or logical group of rows as a separate document entry. This approach maintains the structural integrity of tabular data, ensuring that important financial information presented in tables remains coherent and usable.

For visual content like infographics and cheatsheets, the Catalog Search - Vision pipeline uses the Qwen2 vision model to extract text, diagrams, and visual elements into structured markdown. This multi-pass approach ensures that important visual representations of financial concepts are properly captured and made accessible through text-based search, bridging the gap between visual and textual information.

Very large reference materials such as IFRS Standards are processed through the Semantic Search - Large pipeline. This sophisticated approach preserves hierarchical document structure while creating optimally sized chunks for semantic search. It generates comprehensive metadata including summaries, applicable standards, and contextual information to support vector-based similarity search with advanced reranking and context expansion capabilities.

The document transformation process includes several key steps: Format Standardization across diverse document types, Structure Preservation to maintain hierarchical relationships, Metadata Enrichment to support sophisticated retrieval, and Retrieval Optimization tailored to different search approaches. These carefully designed processes ensure that financial information from diverse sources remains accessible, coherent, and contextually relevant.

5.3 System Inputs and Database Structure

IRIS operates primarily on conversation history and content retrieved from its database structure. The system processes user queries through a sequential pipeline, beginning with the complete conversation history as the initial input. The Agent Router analyzes this history to determine whether to use only conversation context (Direct Response path) or to retrieve information from databases (Research path).

For queries following the Research path, the system performs additional processing: evaluating context sufficiency through the Agent Clarifier, selecting relevant knowledge sources via the Agent Planner, retrieving information using specialized methods through Database Subagents, and synthesizing findings with the Agent Summarizer. Throughout this process, specialized system prompts guide each component's behavior.

The system primarily processes three types of inputs: Conversation History containing complete user-system interaction records, PostgreSQL Database Tables providing structured document content and metadata, and Specialized Prompts containing function-oriented instructions for each agent component. Each component in the pipeline processes these inputs differently based on its specific role in the system.

For semantic search capabilities, the system uses the text-embedding-3-large model configured to generate 2000-dimensional vectors (rather than its maximum 3072 dimensions) to fit PostgreSQL database limits. This creates efficient vector representations of document chunks that enable sophisticated similarity-based retrieval while working within database constraints.

The IRIS system is designed for continuous improvement through regular documentation updates and processing enhancements. Documentation updates include scheduled refresh cycles to incorporate policy changes and expansion of the knowledge base to cover additional finance domains. Processing enhancements focus on improvements to visual content processing for complex financial diagrams and better preservation of document relationships and cross-references. The system's modular design allows for component-level improvements without requiring complete system redesign.

Key Difference: Streaming Response

This agent streams output in real-time. Unlike the Router which waits for a complete response, the Direct Response Agent yields text chunks as they arrive from the LLM, allowing the user to see the response being generated.

Router Agent

Streaming: No
Output: Single decision object
Tool calling: Yes (forced)

Direct Response Agent

Streaming: Yes
Output: Text chunks + usage details
Tool calling: No (plain text)

Parameter Value
Model config.MODEL_LARGE → gpt-4.1
Temperature 0.0 (fully deterministic)

Messages Sent to LLM

[ {"role": "system", "content": "<system_prompt from database>"}, {"role": "user", "content": "<user_prompt with {{conversation}} replaced>"} ]
Why 16,384 max tokens? Direct responses can be lengthy explanations, summaries, or detailed answers. The higher limit allows for comprehensive responses without truncation.
4
Process Streaming Response

The LLM response arrives as a stream of chunks. Each chunk is processed and yielded to the client:

Stream Processing Logic

for each item in response_stream: if item is usage_details dict: // Final item — save and exit loop save usage_details break if item has text content: // Extract text from: item.choices[0].delta.content yield text_chunk // Send to client immediately

When This Agent is Used

Direct Response is chosen when:
  • Follow-up questions about previous responses
  • Clarifications or rephrasing requests
  • General knowledge questions
  • Conversation context contains the answer
  • No specific document lookup required

Example Scenarios

User Says Why Direct Response
"Can you explain that in simpler terms?" Rephrasing previous response — no new research needed
"What did you mean by 'risk-free rate'?" Clarification of previous content
"Thanks, that's helpful!" Acknowledgment — simple response
"How does that compare to last quarter?" If previous response already contained the comparison data

What Happens Next

End of flow. After the Direct Response Agent completes streaming, the response is delivered to the user and the request is complete. No further agents are called — this is the "fast path" that skips database research entirely.

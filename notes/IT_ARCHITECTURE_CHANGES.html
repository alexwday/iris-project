IRIS Architecture Changes

High-Level Overview for IT Deployment

Key Message: We started with a copy of IT's current IRIS code and only modified src/ Python files within the model and utility code. Changes should be copy/paste compatible with IT's environment. Entry point remains chat_model/model.py - no import path changes required.

6. Database Subagents → Unified 2-Stage Retrieval

Separate Internal/External Paths → Single Unified Architecture
Before
services/src/agents/database_subagents/ ├── catalog_search/ ← Internal DBs only │ └── subagent.py (CAPM, Wiki, Memos, etc.) │ ├── semantic_search_v2/ ← External DBs only │ └── subagent.py (EY, IASB) │ └── database_router.py ← Routes to different subagents based on DB type
After
services/src/agent/tools/ ├── metadata_subagent.py ← Stage 1: ALL databases │ Per-document 3-way decision: │ • "answered" → Use metadata finding │ • "irrelevant" → Skip document │ • "needs_deep_research" → Go to Stage 2 │ ├── file_research_subagent.py ← Stage 2 (if needed) │ Deep analysis only for flagged docs │ └── database_router.py ← Unified orchestration Single code path for all DBs
All databases now use the same 2-stage retrieval. No separate code paths for internal vs external.

7. PostgreSQL Tables

Multiple Tables → Unified Schema
Before
┌─────────────────────────────────────────┐ │ apg_catalog (internal docs) │ ├─────────────────────────────────────────┤ │ apg_content (internal sections) │ ├─────────────────────────────────────────┤ │ iris_textbook_database (external) │ ├─────────────────────────────────────────┤ │ process_monitor_logs │ └─────────────────────────────────────────┘ Python dict: AVAILABLE_DATABASES
After
Status Table Purpose
NEW iris_database_registry Replaces AVAILABLE_DATABASES dict
NEW iris_document_metadata Unified: all document metadata
NEW iris_document_chunks Unified: all chunks (internal + external)
EXISTS prompts Aegis prompts table (already exists)
UNCHANGED process_monitor_logs No changes needed
KEEP apg_catalog Backward compat during migration
KEEP apg_content Backward compat during migration
Schema highlights: UUID primary keys (not SERIAL), pgvector embeddings (2000 dims), JSONB for per-database config

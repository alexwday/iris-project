1. Database Registry

IRIS databases are categorized by their search method:

  • Catalog Search - Used for internal databases; processes PDFs to extract metadata and content sections
  • Semantic Search - Used for external databases; processes large documents with embeddings for semantic similarity search

2.2 Catalog Search Refresh For Internal Databases

Processes PDF documents to extract metadata and content sections for catalog-based search.

Stage Script Description Input Output
Stage 1 stage1_extract_csv.py Compares NAS files vs master CSV; identifies new, updated, and deleted files NAS file system + master CSVs 1C_nas_files_to_process.json
Stage 2 stage2_process_documents.py Extracts document content using Azure Document Intelligence (prebuilt-layout model) PDF files from Stage 1 list Markdown files in 2B_outputs/
Stage 3 stage3_generate_summaries.py Generates AI summaries (document_description and document_usage) using GPT Markdown files from Stage 2 3A_catalog_entries.json
Stage 4 stage4_update_csv.py Updates master CSVs with new entries; deletes removed records Stage 1 delete list + Stage 3 entries Updated master_catalog.csv and master_content.csv
Stage 5 stage5_output_final_csv.py Creates timestamped deployment files; archives processing run Updated master CSVs Timestamped CSVs for IT pickup + archive zip
Configuration: Document sources are configured in the DOCUMENT_SOURCES variable in each stage script. Format: source_name,detail_level (one per line, # for comments)

Processes large documents with chapter/section structure and generates embeddings for semantic similarity search.

4. Adding a New Database

Step 1: Create Folder Structure

  • Create the input folder on NAS: [NAS_BASE_PATH]/[database_name]/
  • If prep is needed, also create: [NAS_BASE_PATH]/[database_name]_raw/
  • Place source files in the appropriate folder (raw files in _raw, PDFs in main folder)

Step 2: Configure Refresh Process

Edit the DOCUMENT_SOURCES variable in the refresh stage scripts:

File: catalog search/stage1_extract_csv.py (and other stage files)

DOCUMENT_SOURCES = """
internal_cheatsheets,detailed
internal_esg,standard
internal_[new_db],standard  # Add this line
"""

Detail levels: detailed, standard, concise

Step 3: Run Database Refresh

  • Execute the full catalog search refresh (all stages) in Dataiku
  • Verify the new database appears in master_catalog.csv

Step 4: Add Database Definition

File: services/src/global_prompts/database_statement.py

Add to AVAILABLE_DATABASES dict:

"internal_[new_db]": {
    "name": "Human Readable Name",
    "description": "Description of the content...",
    "query_type": "semantic search",
    "content_type": "policies / guidance / etc.",
    "use_when": "Tier 1 (Domain Specific): Description of when to use. **Strategy:** Query guidance. **Query:** Search term suggestions.",
},

Add to questions_mapping dict (for quarterly testing):

"internal_[new_db]": [
    "Sample question 1?",
    "Sample question 2?",
    "Sample question 3?",
    "Sample question 4?",
],

Step 5: Configure Database Router

File: services/src/agents/database_subagents/database_router.py

For Catalog Search (internal databases): Add to INTERNAL_DATABASES dict:

INTERNAL_DATABASES = {
    ...
    "internal_[new_db]": "internal_[new_db]",
}

For Semantic Search (external databases): Add to EXTERNAL_DATABASES dict:

EXTERNAL_DATABASES = {
    ...
    "external_[new_db]": {
        "query_type": "single_document",  # or "multi_document"
        "documents": {"document_name": 20},  # chunk limit per document
    },
}
Important: You MUST add the database to BOTH AVAILABLE_DATABASES (database_statement.py) AND the appropriate routing dict (INTERNAL_DATABASES or EXTERNAL_DATABASES in database_router.py). Missing either will cause the database to fail.

Step 6: Configure AD Group Access

  • Request new AD group creation from IT (if needed)
  • Update AD_GROUP_MAPPING in production environment configuration

Step 7: Deploy & Verify

  • Deploy code changes through standard release process
  • Verify new database appears in IRIS UI database list
  • Test sample queries against new database

5. Quarterly Model Testing

Purpose: Model Risk compliance - evaluate model accuracy on representative queries each quarter

5.1 Resources

Blank Test Template (Excel) [Link to Excel template]

5.2 Testing Process

  1. Prepare Test Set
    • Take the current set of 50 default test questions
    • Delete 10 questions from the set
    • Go to Tableau dashboard and identify top 10 real user queries from the quarter
    • Add these 10 real queries to replace the deleted ones
    • Save updated set as the new default for next quarter (in Confluence)
  2. Execute Testing
    • For each of the 50 questions:
    • Enter question into IRIS UI
    • Copy question + answer into Excel template
    • Rate response quality on scale 1-10
  3. Aggregate Feedback Metrics
    • Pull thumbs up/thumbs down counts from Tableau dashboard for the quarter
  4. Update Performance Tracking
    • Insert results into performance tracking metrics table
    • Check for threshold breaches (flag any metrics outside acceptable range)
  5. Submit to Model Risk
    • Fill out Model Risk's quarterly template with metrics from tracking table
    • Submit to Model Risk team by deadline

7.4 Architecture Summary

Internal Databases use the Catalog Search method:

  • Documents processed by Azure Document Intelligence
  • Content stored in apg_catalog and apg_content tables
  • Search uses document metadata and section content

External Databases use the Semantic Search method:

  • Documents chunked and embedded (text-embedding-3-large, 2000 dimensions)
  • Content stored in iris_semantic_search table with pgvector
  • Search uses vector similarity with configurable chunk limits
